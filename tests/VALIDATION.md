# From-scratch builder verification — 23 September 2026

Package: `1.2.0-dev.3`, development only. Native desktop Excel through Codex; no release published. Runner arguments and manifest schema are unchanged.

- **Current colour correction:** dev.2 incorrectly used `#FFFF00` and validated that same value. Dev.3 uses the documented `#FFFF66` for every manual input and list value, with blue `#1950FF` font. A fresh 48-month build passed the full runtime verification. Independent saved-file inspection confirmed the exact fill/font on all **32 input/list cells**, including Checks!C38, which now also has explicit runtime colour assertions. Manifest asset hashes match. A formatting-only change did not warrant repeating the full calendar matrix or large-file benchmark.
- **Regression baseline:** dev.2 passed 17 tests: a package with no Excel workbook or input map, eight valid calendar configurations and eight rejection cases. All cases built from empty workbooks. Calendar logic, runner arguments and manifest schema remain unchanged in dev.3.
- **Layout baseline:** the eight regression outputs and four-year example passed formula-cache, header font/fill and output-map inspections. Native Excel previews covered all six sheets, including partial-period wrapping. Input-colour verification is superseded by the dev.3 correction above.
- **Four-year example:** the January 2025–December 2028 USD example, with last actuals August 2026 and calendar financial year, was verified and then deleted with its sidecars at the user's request. The original v1.1 workbook remains unchanged and is not a build dependency.
- **Measured performance:** the final eight regression builds took 6.64–8.92 seconds each. The separately saved four-year example took approximately 16 seconds through saving/closing. Excel and local storage affect timings; these are observations, not guarantees.
- **Large build:** an empty workbook was populated with the six-sheet layout plus 800,000 synthetic text cells and 400,000 simple formulas, producing a **49,212,581-byte** file in **23.57 seconds**. This included 2.01 seconds for base construction, 8.84 seconds for payload creation, 1.04 seconds for calculation/verification and 11.59 seconds for saving/closing. It tests large native construction; it is not directly comparable to the earlier copy-based benchmark and does not represent every financial model's calculation complexity.
